# 十万行实现任务的三条构建路线

本轮选 SymPy 挖空，理由是可以把一道题交付前就要回答的两个问题落实到文件和行为上。其一，固定版本的哪些生产实现已经从 starter 拿掉。其二，恢复哪些可组合的行为才能通过验收。历史仓库按这些行为检索，用独立实现补足多语言上下文。

| 路线 | 怎样得到可运行的第一题 | 主要成本与淘汰条件 |
| --- | --- | --- |
| 先写规格，再找仓库 | 例如要求实现离线 Git 的对象读写、索引、提交遍历和三路合并。先用互操作向量明确输入、输出和冲突语义，再分别在 libgit2、JGit、Dulwich 中找相应实现。官方 Git 可以在评分端生成期望结果。[pack 规范](https://git-scm.com/docs/gitformat-pack) · [index 规范](https://git-scm.com/docs/gitformat-index) | 最方便设计跨实现验收。自编规格要额外证明工作量，找到 gold 后仍要测量对应生产实现，并检验调用现成工具的短实现是否能拿满分。没有对应实现清单时只能标为规格候选。 |
| 挖空成熟实现，再按功能检索 | 固定 SymPy 版本，选取可以分别验收、又能组合调用的功能族。保留公开接口和调用方，把每个被替换的实现定位到源码。以功能名和输入输出语义去查找历史仓中的原生实现，保留有真实路径的命中。 | 最早可以冻结缺失代码量和 gold。包初始化容易连锁失败，需区分导入失败和算法失败。用模块级消融与跨模块题核验，检查不同导入路径或环境中已有同版本安装是否绕过待实现代码。 |
| 从版本演进重建里程碑 | 给旧版本和面向用户的新行为，按能力收拢一组 PR，以新版本为 gold。例子是 SymPy 将矩阵迁移到 DomainMatrix，并逐步加入稀疏／稠密、精确域运算和无分数求解。可验证整数矩阵方程的恒等式 `A*xnum == den*b`。[迁移 PR 及其子 PR](https://github.com/sympy/sympy/pull/21626) · [矩阵契约](https://docs.sympy.org/latest/modules/polys/domainmatrix.html) | 最接近日常升级工作。需要在两端重建依赖、保留旧行为回归测试，并区分功能增加与文件搬移、格式化、依赖更新。相同逻辑跨 PR 重写只能计一次。 |

版本演进有一个可复核的筛选结果。取 SymPy 1.5.1 和 1.13.3 两端的源码归档，枚举 `sympy/polys/matrices/` 下排除 `tests/` 的 Python 文件，分别得到 0 个、15 个文件，共 0 和 10,262 物理行。后一数值还含文档、注释和空行，描述的是这个目录的上限。这个目录可以出一道好题，但单靠它达不到 100k。要扩题，每个新增目录都需要独立的功能依据和测试。[1.5.1 源树](https://github.com/sympy/sympy/tree/70381f282f2d9d039da860e391fe51649df2779d/sympy/polys) · [1.13.3 源树](https://github.com/sympy/sympy/tree/b4ce69ad5d40e4e545614b6c76ca9b0be0b98f0b/sympy/polys/matrices)

## 怎样解释 100k

每次冻结分别报告历史仓库按仓、按语言的源码量，实际被检索器索引的文件数与行数，以及从 gold 实际拿掉的生产实现量。目标规模以最后一项为准。逐文件列出 gold 和 starter 的计数及其差额，说明空行、注释、文档字符串、测试、生成文件和保留接口的处理方式。路径改名、重复拷贝和重复掩码需要去重。物理行和实现代码行使用各自的单位。

这个差额描述参考解的实现规模。相同语义可以由更短的程序实现，提交得分依据行为。验证规模是否有意义，还要记录每个功能族被隐藏用例触达的路径、逐族消融所损失的用例，以及组合调用成功的层数。gold 通过且 starter 失败仅说明至少存在一个可区分的行为。如果大量用例共用一个因导入失败而崩溃的入口，就只能据此判断入口失效。公开源码还可能已进入模型训练集，隔离本机 gold 和屏蔽联网只能控制运行期取源码的途径。

## 从样例接入现有 runner

旧 Poly L1 的 127,999 行是三个历史仓库的索引量。它已经有 gold、starter、逐模块消融和独立评分，适合沿用正负对照和评分分母。新任务还要单独登记缺失实现量。旧协议把 `RealFixture.modules` 的一个模块绑定到一个可写路径，`publicTask` 的固定范围最多 256 个文件，`openRealIndex` 即使复制整个历史目录，实际投影的文件仍须出现在 `referenceFiles` 清单。直接挂上大型目录，会把下载、索引和模型可读规模混在一起。[Poly L1 报告](../../results/poly-v4.md) · [fixture 类型](../real-projects/types.ts) · [可读范围](../real-projects/inputs.ts) · [索引投影](../real-projects/method-index.ts)

正式接入时可把一个行为族映射到一个多文件工作包，保留统一的目标目录，按当前工作包分页读取与编辑。历史索引从独立的冻结清单构建，分别核对下载、支持扫描、实际投影和可供读取的文件。无历史组沿用相同 starter 和 Read/Edit 能力。记录固定模型、每题总预算、工作包间如何传递已完成状态和统一停止条件。独立评分端持有 gold、隐藏用例及上游缓存，执行候选代码的环境只挂载相应试验组的输入。

## 配对测量

以下三组是建议的下一阶段试验。每个配对共用 starter、规格、公开检查、隐藏评分、方法、模型版本、总 token／时间限额和运行环境，随机轮换运行顺序。每次运行使用干净工作区，索引冷启动单列计时。

| 条件 | 给解题方的历史资产 | 这组比较能回答什么 |
| --- | --- | --- |
| 无历史 | starter 和公开契约 | 提供无外部资产时的交付基线 |
| 功能匹配 | 按功能检索并冻结的多语言独立实现 | 与无历史配对，量出引入可复用资产后的行为得分和成本变化 |
| 等规模错配 | 用同语言构成、相近文件数／SLOC 和文件大小分布的其他仓替换相关资产。提前检查其功能与本题无关 | 与匹配组配对，区分功能相关性带来的增益。仅打乱相同文件的顺序仍然能检索到相同实现，无法充当这组对照 |

先在 gold、starter 和逐功能族消融上验证评分，再跑模型。每次输出整题通过、每族通过数与分母、各族等权平均、跨族端到端通过、token、时间和停止原因。分别报告“匹配减无历史”和“匹配减错配”的同题差值。人工标记的相关历史文件用于评估检索召回，留在评分端。单题与少数重复适合诊断，跨任务稳定收益需要扩充独立任务后再估计。

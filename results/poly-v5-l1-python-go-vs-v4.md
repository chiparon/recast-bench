# Poly L1 · Python 与 Go 的 v4 / v5 正式对比

模型为 GPT-6 Luna。每个批次均为两道 L1 题 × 四种方法，每个组合采样一次。两版的项目起始源码树与整题黑盒用例一致，每题实际进入索引的共享历史源码为 127,999 行。v5 使用模块级编译和验收，并按评分、匹配的依赖顺序执行 Python 流水线。

整题通过要求取得有效的 Git 交付提交、通过完整性检查和全部外部行为验收。每题耗时使用 wallMs，包含失败试验、SAG2 建索引和交付评分。token 采用服务端报告的输入与输出总量。

## 模块验收记录

- Python 的 SAG2 和 RECAST 均通过评分模块的编译与局部验收，随后停在匹配模块。SAG2 的匹配模块验收失败五次，最后一次模型请求返回 HTTP 400 `invalid_prompt`，没有 token 回执。表中该组的 token 数值为已报告下限。
- Go 的 SAG2 和 RECAST 均通过计数器编译，进入滚动窗口行为测试。SAG2 的计数器用例从 12/16 升至 14/16，RECAST 为 12/16。两组都在计数器阶段停止。

v5 的 8 份交付输出已按冻结骨架重新验收，并逐项比对模型、用例结果与用量。每个组合仅执行一轮。
